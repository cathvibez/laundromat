EXPERIMENT A -- CIRCUIT BREAK A/B SMOKE TEST
================================================================================
Date run      : 2026-08-04
Rules version : brief v8 (design/game-brief.md), engine sim/rules.py, 87 tests green
Run by        : direct shell invocation (no agent), single-threaded
Purpose       : Confirm the three Circuit break arms are wired up and diverge, and
                size a larger decision run.  This is a SMOKE TEST, not a decision run.

--------------------------------------------------------------------------------
1. HYPOTHESIS UNDER TEST
--------------------------------------------------------------------------------
design/rules-v0.4.md derived analytically that Circuit break as currently written
(arm V2) is oppressive at 5-6 players:

  - Recovery takes P+1 days, because the keyholder restores one machine per day.
  - The board refills in ~3.1-3.6 days, i.e. faster than it recovers.
  - Once Gang is spent and Jimothy is on the board, the event deck is exactly
    {Circuit break, Animal control}, so every second event is another blackout.
  - PREDICTION: steady state of only 1.89 of 7 washers running at six players.

The designer's physical playtests had not surfaced this, hypothesised to be because
the pathology is player-count dependent and mild at 3-4 players.

--------------------------------------------------------------------------------
2. ARMS
--------------------------------------------------------------------------------
V0  "none"          Control -- Circuit break removed from the game entirely.
                    *** NOT VALID IN THIS RUN.  See section 6. ***
V1  "blackout"      Only that night's reckoning is cancelled.  Machine power states
                    are untouched; everything resumes normally the next day.
                    (This is the original Electricity behaviour.)
V2  "all off"       Every live washer switches OFF; the keyholder restores one per
                    day.  This is the rule as written in brief v8.
V3  "auto-restore"  Every live washer switches OFF, but all machines come back ON at
                    the end of the FOLLOWING day's reckoning.  Middle option, added
                    by Claude because it costs nothing to test alongside.

Selected via cfg['circuit_break'] = 'V1' | 'V2' | 'V3'.

--------------------------------------------------------------------------------
3. DESIGN
--------------------------------------------------------------------------------
Games per cell      : 500
Player counts       : 3, 4, 5, 6
Machines            : P + 1  (4, 5, 6, 7)
Capacity            : 4, flat
Bot policy          : CLUSTERING only (closest model of real table play)
Seeds               : 0..499, IDENTICAL across arms (common random numbers, so
                      arms are paired on starting hands and dice)
Total games         : 500 x 4 arms x 4 player counts = 8,000  (first pass)
                      500 x 3 arms x 4 player counts = 6,000  (corrected pass)
Wall clock          : 63.9s for 8,000 games, single-threaded (~125 games/sec)

Metrics captured (per game, then averaged):
  days                    game length in days
  machines_live_days / d  machines not destroyed by Gang
  machines_avail_days / d PRIMARY -- live, ON, no raccoon: what a player can load into
  on_machines_sum / d     machines switched ON
  wash_events / (d * P)   throughput per player-day
  cb_days                 number of Circuit break firings per game
  cb_lost_machine_days    machine-days removed from play by Circuit break

--------------------------------------------------------------------------------
5. FINDINGS
--------------------------------------------------------------------------------
5.1  THE SHAPE OF THE HYPOTHESIS IS CONFIRMED.  V2's damage scales sharply and
     monotonically with player count and is negligible at 3 players.  This explains
     why physical playtesting had not surfaced it: at 3-4 players V2 is essentially
     free, and it is specifically the 5-6 player game it damages.

5.2  THE MAGNITUDE WAS OVERSTATED BY THE ANALYTICAL MODEL.  rules-v0.4.md predicted
     1.89 of 7 machines running at six players under V2.  Measured: 4.10.  The model
     was off by more than 2x.  Likely cause: games last only ~10-12 days, so the
     {Circuit break, Animal control} endgame deck state rarely persists long enough
     for the death spiral to compound.  Circuit break fires ~2.8 times per game at
     six players, not every other event.

     Consequence: this is a real, measurable, player-count-dependent tax -- not the
     emergency it was first reported as.

5.3  V3 ROUGHLY HALVES THE DAMAGE.  At six players it cuts machine-days lost from
     30.6 to 13.2 and the length penalty from +2.18 to +0.81 days, while keeping the
     card meaningfully threatening.

5.4  V1 MAY BE TOO WEAK.  It costs ~0 days at every player count and removes zero
     machine-days.  Whether it is distinguishable from having no card at all is
     UNKNOWN -- see 6.1.

--------------------------------------------------------------------------------
6. VALIDITY THREATS AND KNOWN DEFECTS OF THIS RUN
--------------------------------------------------------------------------------
6.1  THE V0 CONTROL IS INVALID.  The first pass passed cfg['no_circuit_break']=True,
     which the engine does not implement and silently ignored.  V0 therefore ran an
     identical configuration to V1 and produced byte-identical results.  The question
     "how much does Circuit break cost the game at all?" remains UNANSWERED.
     Fixing this requires a small engine change to omit the card from the event deck.

6.2  FIRST PASS USED WRONG METRIC KEYS.  Claude guessed stat key names that do not
     exist, so the primary metric (available machines) reported n/a throughout.  The
     corrected pass in section 4 uses the real keys.  The first pass is superseded and
     is not reproduced here.

6.3  UNDERPOWERED FOR SMALL EFFECTS.  500 games per cell.  The 6-player differences
     are far larger than noise; the 3-player differences (0.02-0.06 days) are well
     inside it and must not be interpreted.

6.4  SINGLE POLICY.  CLUSTERING only.  Whether GREEDY shows the same pattern is
     untested.

6.5  NO CONFIDENCE INTERVALS computed.  Point estimates only.

--------------------------------------------------------------------------------
7. RECOMMENDATION
--------------------------------------------------------------------------------
Ship V3 "auto-restore", pending confirmation by a larger run.

Rationale: V2 fails the pre-registered criterion of "no sharp degradation from 3 to 6
players."  V1 passes it but appears to make the card nearly inert.  V3 keeps the card
threatening while roughly halving V2's high-player-count penalty.

If the game's primary configuration is 3-4 players, V2 as written is acceptable and no
change is needed.
